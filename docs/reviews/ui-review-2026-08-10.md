# Agent DevTools UI 审查（light / dark 双主题）

- 审查日期：2026-08-10
- 审查对象：`claude/review-fixes-2026-08-10` 分支（`5af9e5b`）的 SPA，`src/web/**`
- 标准来源：`AGENTS.md`（UI conventions）、`design.md/design-claude.md`（设计系统与命名色值）、WCAG 2.1 AA
- 方法：`styles.css` token 静态解析 + WCAG 对比度计算 + Chromium 实测（两套主题各自截图、逐元素几何比对、键盘焦点遍历），驱动数据来自灌入真实流量的本地代理

## 结论摘要

结构性的东西是干净的：**token 跨主题奇偶性 43/43 完整**，**布局不随主题变化**（177 个元素逐一比对，仅 3 处差异且全部落在主题切换图标自身的 SVG 内），**两套主题的键盘焦点指示都可见**，组件里**没有字面颜色**（shadcn 的两个遮罩除外）。

问题几乎全部集中在**颜色对比度，且严重偏向 light 主题**：

| | 低于 AA 的配对 |
| --- | --- |
| light | **11** |
| dark | **2** |

最严重的是 light 主题的品牌强调色 `--primary`（coral `#cc785c`）——它在**自己的每一种主要用法上都不达标**：按钮上的白字 3.28，作为链接文字 3.11，作为选中行的边框 2.89。同一批用法在 dark 下是 7.73。其次是六种 badge 色调在 light 下**全部**低于 AA（3.85–4.48），而在 dark 下全部 6.25–11.66。

另有一处 dark 专属的结构问题：`--color-code` 与 `--color-surface-soft` 在 dark 下是**同一个值**，而六处 code 卡片没有加边框，导致它们的边界在 dark 下完全消失——`styles.css` 自己的注释已经写明 dark 需要这条边框。

## 对比度

### [高] UI-01 light 主题的强调色在全部主要用法上低于 AA

- **位置**：`src/web/styles.css:214`（`--primary: #cc785c`）
- **实测**（light）：

  | 用法 | 代码 | 比值 | 要求 | |
  | --- | --- | --- | --- | --- |
  | 激活态 tab / 模式按钮上的白字 | `ui.tsx:80`、`ContentViewer.tsx:150` | **3.28** | 4.5 | ✗ |
  | `inspect →` 链接文字 | `TraceView.tsx:110` | **3.11** | 4.5 | ✗ |
  | 选中行左边框 vs `surface-soft` | `TraceView.tsx:90` | **2.89** | 3.0 | ✗ |
  | 选中会话左边框 vs `surface-card` | `ConversationList.tsx` | **2.71** | 3.0 | ✗ |

  同样四项在 dark（`--primary: #7aa2f7`）分别是 7.73 / 7.73 / — / —，全部通过。
- **影响**：这不是边角料。激活态 tab、每一个被按下的 `Rendered · MD` / `Diff Left` 按钮、每一条 `inspect →`、选中行的指示条，是这个界面里状态反馈的全部载体。
- **可用修法**：`design.md/design-claude.md:328` 已经定义了同色系的更深变体 `primary-active: #a9583e`。它把四项分别提到 5.06 / 4.80 / 4.46 / 4.19，全部达标，且色相不变——是设计系统自己的颜色，不是新造的。

### [中] UI-03 `--color-muted-soft` 两个主题都低于 AA

- **位置**：`src/web/styles.css:81`（light `#8e8b82`）、`:159`（dark `#616d78`）
- **实测**：

  | | canvas | surface-soft | surface-card |
  | --- | --- | --- | --- |
  | light | **3.23** | **3.00** | **2.82** |
  | dark | **3.68** | **3.52** | **3.13** |

- **用在哪**：空状态文案、会话列表时间戳、`showing first 800 frames of N`、工具条元信息、Network 选中行的 kind 标签——都是真实信息，不是装饰。

### [中] UI-04 `--muted-foreground` 在 `surface-card` 上低于 AA

## 主题一致性

### [高] UI-05 六处 code 卡片在 dark 下没有边界

- **位置**：`App.tsx:297,302`（header 的运行命令块）、`Inspector.tsx:451`（SSE 帧列表）、`Inspector.tsx:487`（展开的帧正文，`bg-code-soft`）、`ui.tsx:281`（`CopyIconButton` 的 code 表面）、`TraceView.tsx:248`（工具 INPUT/RESULT 面板）
- **实测**：

  | | code vs canvas | code vs surface-soft |
  | --- | --- | --- |
  | light | 17.00 | — |
  | dark | **1.04** | **1.00**（`--color-code` 与 `--color-surface-soft` 在 dark 下是同一个值 `#101317`） |

- **与规范的关系**：`styles.css:23-28` 的注释已经写明了机制——「In dark it becomes a *raised* panel (slightly lighter than the canvas, with a visible border), because near-black on near-black would erase the boundary the card exists to draw.」`--color-code-border` 这个 token 就是为此存在的（light 下等于 `--color-code` 故不可见，dark 下 `#232a33`）。这六处只是没用它。
- **证据**：dark 截图里 header 的 `ANTHROPIC_BASE_URL=…` 块完全读不出卡片形态，退化成一段浮在画布上的等宽文字。
- **可用修法**：六处补上 `border border-code-border`。light 不受任何影响（该 token 在 light 下与卡片同色，正是设计意图）。

### [中] UI-06 模态遮罩在 dark 下等于不存在，且是组件里的字面颜色

- **位置**：`src/web/components/ui/drawer.tsx:75`、`src/web/components/ui/dialog.tsx:32`，均为 `bg-black/10`
- **实测**：遮罩后画布与原画布的分离度——light `1.254`，dark **`1.007`**。
- **影响**：dark 下 Git Diff 对话框与其背后的页面几乎同色，只靠一条 hairline 区分，模态边界很弱。Drawer 因为还有 `backdrop-blur` 尚可，Dialog 没那么幸运。
- **与规范的关系**：`AGENTS.md` 要求「Use role-named CSS variables from `src/web/styles.css`; do not put literal color decisions in React components」。`bg-black/10` 同时违反了这条，也是它无法随主题变化的根因。
- **可用修法**：新增 `--color-overlay` 角色，light 用暖黑约 28%、dark 用纯黑约 62%，组件改用 `bg-overlay`。一处修改同时解决字面颜色与 dark 失效两个问题。

## 检查过且判定良好的部分

记录下来，避免后续重复劳动：

- **Token 跨主题奇偶性**：`@theme` 定义了 43 个 `--color-*`，`[data-theme='dark']` 全部 43 个都做了覆盖，没有任何一个 light 值会漏进 dark。
- **布局不随主题变化**：两套主题下对 177 个元素逐一比对 `getBoundingClientRect`，仅 3 处差异，全部位于主题切换按钮内部的 SVG（月亮 1 个 `path` vs 太阳 `circle` + `path`）——图标显示的是「点了会切到哪个主题」，是有意设计。`AGENTS.md`「Do not make theme selection change layout, spacing, or content」成立。
- **键盘焦点**：两套主题各遍历 14 个 tab stop，全部有可见焦点指示（来自 `styles.css:601-605` 的 `@layer base` 规则）。Chromium 的 `outline-style: auto` 会绘制自带的高对比双色环，不受 token 透明度影响。
- **组件内无字面颜色**：`src/web/**/*.tsx`（除 shadcn 生成的两个遮罩外）没有任何 hex / rgb / Tailwind 调色板类名。
- **深色 code 面板上的文字**：两套主题下 JSON 语法色、SSE event、工具输出、Raw 面板全部在 6.62–17.00 之间，无一低于 AA。
- **XML 大纲配色**：light 4.66–10.34，dark 5.38–10.57，全部达标。
